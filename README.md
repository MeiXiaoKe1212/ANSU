# ANSU 运输中介管理系统

这是一个专为运输中介业务设计的管理系统，帮助您记录、管理和统计运输订单，实现业务数字化管理。

## 项目结构

```
ANSU/
├── ansu-api/          # 后端API服务 (Spring Boot)
├── ansu-h5/           # 前端H5应用 (Vue 3)
└── README.md          # 项目说明文档
```

## 功能特性

### 核心业务功能
- **订单管理**: 创建、编辑、查询运输订单
- **状态跟踪**: 运输状态和款项状态实时更新
- **成本管理**: 记录各类运输成本（加油费、过路费、违章费等）
- **利润计算**: 自动计算订单利润和利润率
- **客户管理**: 管理第三方企业客户信息
- **车辆管理**: 管理自有车辆和司机信息
- **外包支持**: 支持第三方平台（如货拉拉）外包订单

### 系统功能
- **多用户支持**: 支持多个同事共同使用系统
- **数据统计**: 订单统计、收入统计、利润分析
- **状态日志**: 记录所有状态变更历史
- **移动端适配**: 响应式设计，支持手机和平板使用

- **ORM**: MyBatis Plus 3.5.4
- **工具库**: Hutool 5.8.29
- **构建工具**: Maven

### 前端 (ansu-h5)
- **框架**: Vue 3.5.17
- **UI组件**: TDesign Mobile Vue 1.9.3
- **状态管理**: Pinia 3.0.3
- **路由**: Vue Router 4.5.1
- **图表**: ECharts 5.6.0
- **构建工具**: Vite 7.0.3

## 数据库设计

### 核心表结构
- `sys_user`: 系统用户表
- `customer`: 客户表（第三方企业）
- `driver`: 司机表
- `vehicle`: 车辆表
- `transport_order`: 运输订单表（核心表）
- `order_cost`: 订单成本表
- `order_status_log`: 订单状态日志表

### 订单状态说明
**运输状态**:
- `CREATED`: 已创建
- `DEPARTED`: 已出发
- `TRANSPORTING`: 运输中
- `EXCEPTION`: 异常
- `DELIVERED`: 已送达

**款项状态**:
- `UNPAID`: 未付款
- `PREPAID`: 已预付费（用于第三方平台外包）
- `PAID`: 已结款

## 快速开始

### 环境要求
- Java 8+
- Node.js 16+
- MySQL 8.0+
- Maven 3.6+

### 后端启动
1. 创建数据库 `ansu_transport`
2. 修改 `ansu-api/src/main/resources/application.yml` 中的数据库配置
3. 启动后端服务：
```bash
cd ansu-api
mvn spring-boot:run
```
后端服务将在 http://localhost:8080 启动

### 前端启动
1. 安装依赖：
```bash
cd ansu-h5
npm install
```

2. 启动开发服务器：
```bash
npm run dev
```
前端应用将在 http://localhost:5173 启动

## 使用说明

### 创建订单
1. 点击主页或订单列表页的"新增"按钮
2. 填写客户信息（企业名称、联系人、电话）
3. 填写运输信息（起点、终点、货物信息）
4. 选择车辆类型（自有车辆或第三方外包）
5. 填写价格信息
6. 提交创建订单

### 管理订单状态
- 在订单列表中可以筛选不同状态的订单
- 点击订单可查看详情并更新状态
- 系统会自动记录状态变更日志

### 成本管理
- 在订单详情页可以添加各类成本
- 支持的成本类型：加油费、过路费、违章费、维修费、外包费、其他
- 系统会自动重新计算利润

### 数据统计
- 主页显示订单总数、总收入、总利润等关键指标
- 支持按状态统计订单数量
- 提供图表展示趋势数据

## 开发说明

### API接口
后端提供RESTful API接口，主要包括：
- `/api/transport-orders/*`: 运输订单相关接口
- `/api/order-costs/*`: 订单成本相关接口

### 前端组件
- `TransportOrderForm.vue`: 运输订单表单组件
- `transportOrderStore.js`: 订单数据状态管理

### 数据持久化
前端使用 Pinia 进行状态管理，并支持数据持久化到本地存储。当后端API不可用时，会自动使用本地模拟数据。
